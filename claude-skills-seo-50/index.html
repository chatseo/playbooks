The map: 50 skills, 8 categories

SEO teams spend hours on the same jobs every week. Each of those jobs is a skill here.

A Claude Skill is one file, SKILL.md: a name, one line saying when to use it, and the instructions. Claude reads only the one-line descriptions until your request matches one, then loads that skill. So 50 skills cost you nothing until you need one.

Every skill follows the same shape:

  • The data Claude needs. Which export, which date range, which filter.
  • A repeatable workflow. The steps, in order, with the thresholds that separate signal from noise.
  • An output template. The exact columns of the table, capped, so you can act on it.
  • The one action to take next. Not a list of ten. One.

The 2-minute setup

  1. Download the zip and unzip it at the root of your site's folder. The skills land in .claude/skills/. To use them in every project, unzip in ~/.claude/ instead.
  2. Restart Claude Code.
  3. Ask normally: "which of my pages should I push first?" loads position-8-15-finder. You can also name a skill: "use title-rewriter on my top 20 pages".

1Keyword Research

Expand seed terms, classify search intent and map every query to the right page. 8 skills.

Skill · .claude/skills/seed-expander/SKILL.md
---
name: seed-expander
description: Turn one seed keyword into a full keyword universe with volume and difficulty. Use at the start of any new topic.
---

Take the seed. Expand via modifiers, questions, comparisons, alternatives, and long-tail variants.
For each keyword: volume | difficulty | intent | whether the site already ranks for it.
Drop anything with zero volume or an intent the site cannot serve.
Cap the output at 50 keywords.
End with the single keyword to build the pillar page around.

description: Classify keywords by search intent so you build the right page type. Use before any content decision.

Base the call on what actually ranks in the SERP, not on the wording of the keyword.
Columns: keyword | intent | evidence from the SERP | correct page type.
Flag any keyword where the SERP shows mixed intent: those need a hybrid page or should be skipped.
End with the one keyword whose intent the site is currently getting wrong.

3Content Creation

Build briefs from the SERP, write first drafts and refresh pages before they decay. 6 skills.

brief-builder · Write a content brief specific enough that the draft is not generic AI mush.
Skill · .claude/skills/brief-builder/SKILL.md
---
name: brief-builder
description: Write a content brief specific enough that the draft is not generic AI mush. Use before writing any page.
---

Analyse the top 10 for the primary keyword. Build a brief containing: target keyword and cluster, search intent, mandatory format, required H2s with the gap each fills, entities and facts that must appear, the angle no competitor has taken, internal links to include, and the CTA.
Every required section must state WHY it is required, citing what ranks.
Ban generic sections: no "Introduction", no "Conclusion", no "What is X" unless the SERP demands it.
End with the one angle that differentiates this page.
outline-from-serp · Build an H2 outline from what ranks plus what nobody covers.
Skill · .claude/skills/outline-from-serp/SKILL.md
---
name: outline-from-serp
description: Build an H2 outline from what ranks plus what nobody covers. Use after the brief.
---

Extract every H2 and H3 from the top 10 results. Cluster them by topic and count frequency.
Sections appearing in 5+ results are table stakes: include them. Sections in 1-2 results are optional.
Then name what NO result covers but the searcher needs. That is the differentiator.
Output the outline with a one-line note per section on what it must contain.
End with the one section that will make this page better than the current number one.
first-draft · Write the first draft from an approved brief, in the site's voice.
Skill · .claude/skills/first-draft/SKILL.md
---
name: first-draft
description: Write the first draft from an approved brief, in the site's voice. Use only after brief-builder.
---

Read the brief and follow it exactly: do not add sections it did not ask for.
Open with the answer, not with context-setting. No "In today's digital landscape".
Every claim gets a specific number, example, or source. If you cannot source it, cut it.
Match sentence length to the site's existing content. Short sentences. Plain words.
End the draft with the CTA from the brief and nothing after it.
eeat-injector · Add real experience and expertise signals to a draft.
Skill · .claude/skills/eeat-injector/SKILL.md
---
name: eeat-injector
description: Add real experience and expertise signals to a draft. Use before publishing anything YMYL or competitive.
---

Read the draft. Find every claim stated without evidence.
For each, specify what would make it credible: a named source, a first-hand result, a screenshot, a date, a methodology note, or an author credential.
Columns: claim | current evidence | what to add | where to get it.
Do not invent experience the author does not have: mark those claims for cutting instead.
End with the one addition that most raises the page's credibility.
content-refresh · Build a rewrite plan for a page that is losing traffic.
Skill · .claude/skills/content-refresh/SKILL.md
---
name: content-refresh
description: Build a rewrite plan for a page that is losing traffic. Use when a page decays.
---

Pull the page's GSC data for the last 90 days vs the prior 90. Identify which queries lost position and which are new.
Compare the page to what currently ranks top 3: what do they cover that it does not, and what has changed since publication.

If the page lost to a different content format entirely, say so: a refresh will not save it.

decay-detector · Find pages losing traffic before the decline becomes serious.
Skill · .claude/skills/decay-detector/SKILL.md
---
name: decay-detector
description: Find pages losing traffic before the decline becomes serious. Use weekly.
---

Compare the last 28 days to the prior 28, and to the same period last year to control for seasonality.
Flag pages down more than 20% that are not explained by seasonality.
For each: URL | clicks then | clicks now | position change | whether it lost position or lost impressions.
Losing impressions at a stable position means the SERP changed, not your page: distinguish the two.
End with the one page to refresh.
