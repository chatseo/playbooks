Each module is one n8n workflow. Each step on the map is one or more nodes, listed in the module's node map below with what it reads and what it writes. The dashed loop is the weekly review: module 7 proposes one change to the thresholds, you approve it, apply it in Config, and module 2 uses it the following Monday.

How it runs: orchestration, approvals, exceptions

  • Central orchestration. 00-orchestrator.json is the only workflow you activate. Monday 07:00 runs modules 1 → 2 → 3 → 4. Every day at 09:00 it starts one approval run per draft, runs tracking, and requeues retried exceptions. Friday 16:00 runs reporting.
  • Human approvals. Two places, both a Slack message with an Approve and a Reject link backed by an n8n Wait node: every page change (module 5) and every process change (module 7). No click within 72 hours = nothing happens.
  • Exceptions → review → retry. 08-exceptions.json is the error workflow of the 8 others: any failed node writes a row to the exceptions tab and pings Slack. Module 5 also logs a page that failed its live QA. You read it, fix the cause, set the row to retry, and the next daily run puts the draft back in the queue.
  • Memory. One Google Sheet, 8 tabs. Every module reads the previous module's tab and writes its own, so you can open the sheet at any point and see exactly where each page is.

Setup

  1. Download the zip. Create a Google Sheet with the 8 tabs in sheets-template/ (header rows only).
  2. Copy config.example.json to config.json, fill in your Search Console property, site, sitemap, sheet ID and Slack channel, then run node configure.mjs. It writes the same values into the Config node of all 9 workflows.
  3. In n8n, create the credentials: Google Sheets; a generic OAuth2 credential for Google with the scope https://www.googleapis.com/auth/webmasters.readonly (Search Console and URL Inspection); Header Auth x-api-key for Claude; Slack; Basic Auth with a WordPress Application Password. Perplexity is optional.
  4. On WordPress, drop wordpress/seo-engine-rest-fields.php in wp-content/mu-plugins/. It lets the REST API write the Yoast SEO title and meta description (two keys to swap for Rank Math).
  5. Import 08, then 01 to 07, then 00. Paste the module IDs into the orchestrator's Run nodes, set "SEO Engine · 8. Exceptions" as the error workflow everywhere, pick the credentials on each node.
  6. Follow the testing checklist before activating the orchestrator.

Priority score · the code node, so you can check the thresholds
Priority score
// Upside = clicks the page would get at the expected CTR (or at position 5 for striking pages), minus what it gets now.
// It is an estimate from YOUR impressions and the Config curve, labelled as such. Pages already open are skipped.
const c = $('Config').first().json.config;
const open = new Set($('Read open opportunities').all().filter(o => !['done', 'rejected'].includes(o.json.status)).map(o => o.json.page));
const today = $today.toFormat('yyyy-MM-dd');
const rows = [];
for (const { json: p } of $input.all()) {
  if (open.has(p.page) || !(p.striking || p.low_ctr || p.decaying)) continue;
  const imp = Number(p.impressions), clicks = Number(p.clicks);
  const reasons = [], ups = [];
  if (p.striking) { reasons.push('positions 8-15'); ups.push(imp * c.ctr_curve['5'] - clicks); }
  if (p.low_ctr) { reasons.push('low CTR for its position'); ups.push(imp * p.expected_ctr - clicks); }
  if (p.decaying) { reasons.push('lost clicks vs previous 28 days'); ups.push(Number(p.prev_clicks) - clicks); }
  rows.push({ id: p.page + '#' + today, page: p.page, reason: reasons.join(' + '),
    clicks, impressions: imp, ctr: p.ctr, position: p.position, prev_clicks: p.prev_clicks,
    top_queries: p.top_queries, owner: p.owner,
    upside_estimate: Math.max(0, Math.round(Math.max(...ups))), status: 'new', created_at: today });
}
return rows.sort((a, b) => b.upside_estimate - a.upside_estimate).slice(0, c.max_opportunities).map(json => ({ json }));

CTR change · the code node, so you can check the thresholds
CTR change
// Did it work? Same-length windows before and after. Under 100 impressions on either side = too early, never a verdict.
const due = $('Due rechecks').all(), before = $('GSC before').all();
return $input.all().map((it, i) => {
  const p = due[i].json, b = (before[i].json.rows || [])[0] || {}, a = (it.json.rows || [])[0] || {};
  const bc = b.clicks || 0, ac = a.clicks || 0, bi = b.impressions || 0, ai = a.impressions || 0;
  const bctr = bi ? bc / bi : 0, actr = ai ? ac / ai : 0;
  let verdict = 'flat';
  if (bi < 100 || ai < 100) verdict = 'too early';
  else if (ac >= bc * 1.2 && actr > bctr) verdict = 'worked';
  else if (ac <= bc * 0.8) verdict = 'dropped';
  return { json: { page: p.page, published_at: p.published_at, change: p.change, window: p.window, main_query: p.main_query,
    clicks_before: bc, clicks_after: ac, impressions_before: bi, impressions_after: ai,
    ctr_before: +bctr.toFixed(4), ctr_after: +actr.toFixed(4),
    position_before: b.position ? +b.position.toFixed(1) : '', position_after: a.position ? +a.position.toFixed(1) : '',
    verdict, checked_at: $today.toFormat('yyyy-MM-dd') } };
});

Demo data and testing checklist

Module 1 ships with synthetic data pinned to its two Search Console nodes and its sitemap node: 10 pages of a made-up SEO blog on example.com, with one page losing clicks and one page missing from the sitemap. Pinned data only runs when you click "Test workflow", never in scheduled runs. The same data is in demo/.

  1. Import 08-exceptions.json first, then 01 to 07, then 00-orchestrator.json. Note each workflow's ID (the number in its URL).
  2. In 00-orchestrator, replace every REPLACE_WITH_ID_OF_0X with those IDs. In every workflow's settings, set Error workflow to "SEO Engine · 8. Exceptions".
  3. Module 1 with demo data: it ships with pinned demo data on the two Search Console nodes and the sitemap node. Add only the Google Sheets credential, click "Test workflow".
  4. Module 2 on those rows. Expect 7 rows in opportunities, the first one /blog/meta-description-length/ (low CTR for its position, upside_estimate 509),
  5. Unpin the demo data in module 1, add the Google OAuth2 credential, run it again on your real property. Check the row count against Search Console > Pages.
  6. Module 3 (needs the Anthropic credential). Every brief row should have status "ready". "needs_human" means Claude's answer was not valid JSON: the raw answer is in parse_error.
  7. Module 4. Check new_title (60 characters or fewer) and the checks column. You should get one Slack message.
  8. Module 5 on a staging site: set one draft to needs_review, run the orchestrator's daily branch by hand. Click Reject first: the draft becomes "rejected". Then repeat and click Approve.
  9. Module 6: add a publish_log row for a real page with published_at 18 days ago. Run it: one tracking row with a verdict ("too early" is normal on small pages).
  10. Module 7: run it, get the Slack digest, click Reject. Run again, click Approve: one changelog row. The engine never edits its own Config: apply approved changes by hand.
  11. Break it on purpose (wrong sheet_id in one module): you should get an exceptions row and a Slack alert.
  12. Activate only 00-orchestrator. The modules are called by it and must stay inactive.

The part the engine can't do alone

The honest gap. The engine moves data, it doesn't have any of its own. Search Console tells it which pages are close, but not what's ranking above them, what those pages cover, how many people search the queries it doesn't rank for yet, or who links to the competition. So the brief in module 3 is written from your page and your queries only, and Claude is told to say "not in the data" rather than guess. That's honest, and it's also where most of the value is missing. Where this breaks

  • It is a blueprint, tested on demo data. Modules 1 and 2 run end to end on the pinned data. Your Sheets columns, credentials and CMS will need the checklist above before you trust a scheduled run.
  • Big sites. One Search Console call returns up to 25,000 rows. Above that, add a loop on startRow in module 1.
  • Sitemap indexes. Point sitemap_url at a child sitemap, or add a loop. Module 1 flags an index instead of pretending.
  • WordPress only, out of the box. Module 5's three CMS nodes are the only WordPress-specific part. Shopify or Webflow: swap those three for their API.
  • Small pages give "too early". Under 100 impressions before or after, there is no verdict. That's on purpose.
  • The CTR curve is a default. Replace ctr_curve in Config with your own site's average CTR by position once you have it.
  • Section drafts are never pasted for you. The engine writes them; a human puts them on the page.

What I'd do tomorrow

  1. Import module 1, run it on the demo data, then on your property. Read the pages tab.
  2. Run module 2. If the top 10 doesn't look like the pages you'd pick by hand, change the thresholds now, not later.
  3. Run 3 and 4 on 3 pages only. Read every brief before anything else gets built on top.
  4. Approve one title change on a page that matters. Wait 17 days for the first recheck.
  5. Only then activate the orchestrator.

Pull. Score. Plan. Write. Approve. Check. Learn. In that order, every week.
